## Summary

Decision: `lines` is a table of input rows on #53's default look. Each row has a muted number, one square field per column and an [×] to remove it, with [add line] under the rows. A total row sums the money columns as you type. A journal's balance line shows a moss "balanced" or a brick "out of balance · credit short by 49.90", and posting stays off until the entry balances and no row has an error. Row errors come from the app's check (as with `editor`): the row gets a brick marker and its message right under it. The block picks its layout by its own width, not the screen's: a table when wide, one stacked group per row when narrow (under 560 px).
Screens: a ledger journal entry that is out of balance with one bad row, plus an invoice with an app-filled Amount; and a sheet of nine states (the fixture, balanced, empty, at the minimum, long text, many rows, fixed lines, focus and saving, a block error). Each is light and dark, at 1440 and 390.
Open questions: (1) qty × price can't be computed in the client, because `expr` has `add` and `sub` but no multiply, so the app fills Amount through its check. Should `expr` get a `mul` instead? (2) On a phone, the totals sit after the last row and don't stick to the screen. Should they stick to the bottom while the block is in view?

## The shape (proposal, for impl to settle against docs/schema.md)

- `lines`: `id`, `name` (the values key), `label` (the group's accessible name, defaulting to `name`), `action` (the check, posted 400 ms after the last change with `{ [name]: rows }`, the same as `editor`), `columns: Vec<Field>` (the existing form `Field` is reused, with no new column type: `picker` with `options`, `text`, `keyboard: number` for numbers, `enabled: false` for an app-filled cell drawn as text), `rows: [{ id, values: Fields }]`, `sum: [column]`, `balance: [debit, credit]`, `scale` (decimals, default 2), `min`, `max`, `add` (the add button's label; leaving it out means fixed rows with no add and no remove), `empty` (the empty row's text), `errors: [{ row?, name?, message }]` (the same as `editor`'s `{ line, message }`), `submit: Submit`.
- Totals are summed as integers in minor units (`scale`), never as floats, and shown with grouping. The balance compares the two sums exactly. The submit is off while the entry is out of balance, while any error stands, or when `submit.off` is set. The app still checks everything again when it receives the entry.
- A new row gets a client id, is added at the end, and focuses its first cell. Removing a row moves focus to the next row's [×], or to [add line] if it was the last. The drafts are kept per screen and block id, as the composer's are, so a redraw with new `errors` keeps what was typed.
- a11y: the root is `role=group` named by `label`. Each row is `role=group` "line N". Each cell is named "Debit, line 3", and each [×] "remove line 3". The balance line is `role=status`, so a change is announced. The column header row is `aria-hidden`, since each cell already has its name.
- Stress fixtures: long-text, empty and many-row, as in states 5, 3 and 6.

## What impl builds

- CSS: `lines.css` here (tokens only, no new colour, square), going into `web/src/blocks.css`. The prefix is `lq`, because `.ln` is already the scene lane's. The wide/narrow switch is a container query on the block (`max-width: 560px`), so a block in a narrow pane at 1440 stacks too. The column widths come from one `--lq-cols` value that the renderer sets: 3ch for the number, 14ch for a summed column, 10ch for any other number, 1.4fr for a picker, 2fr for text, and 32px for [×]. The total row uses the same grid, so each sum lines up under its column.
- SwiftUI draws the narrow layout (a `Grid` when wide), with the same markers and texts. The static writer writes the rows as a read-only `<table>`, with totals in `<tfoot>`. The fallback is that table.
- `lines.js` is a preview-only port that draws these images, not product code. `page.css` stands in for #53's tiles. The colours come from `../neutral-default/tokens.css`. Images: `./render.sh` (Playwright's cached headless Chromium, light and dark, reduced motion).
