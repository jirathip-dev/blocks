## Summary

Decision: a new kind `import` is one card on the screen. It has a drop area with [choose file] and [download template]. After a pick, the card shows the file, then the columns (each matched to a header in the file, with a select to change it) beside the rows as the table draws them. Rows with errors get a red edge with the reason underneath and are left out. One confirm in the action bar, then the accepted rows go to the app as one action and the card shows the count. Files are read on the device by our own small reader for .xlsx and .csv, loaded only when first used, so there is no new dependency. Default look, no new colour.
Screens: the flow (empty, file picked with columns and rows, row errors), the finish (confirm, sending, done, the app refusing rows), and every other state (wrong columns, an unusable file, several sheets, Thai, off, JavaScript off, the template, a table's export). Each is drawn light and dark, at 1440 and 390.
Open questions: (1) No dependency, and our own reader instead (recommended), or a library (below)? (2) The line cap has 163 lines of headroom, and this kind needs roughly 1,200 across Rust, TS and Swift, so a cap raise has to come first either way.

## The kind (for impl)

- Wire name `import`. It is a JS and Swift keyword, so the generated type names are `Import` (Rust, TS) and the Swift case is written with backticks. Fields: `id`, `title`, `into` (what the rows go into, used in the words), `columns`, `action`, `max` (rows, default 5,000), `template` (default on), `error` (the app's message) and `refused` (the app's row errors: spreadsheet row, column key, text). The app's answer `done: {count}` turns the card to done.
- A column: `key`, `label`, `type` (text, number, money, date, choice), `required`, `unique`, `values` (the allowed list for a choice), `also` (other header names it matches). On the phone, the first text column after the key is the title, money is the value, a choice is the tag, and the rest are meta.
- The action sends `{rows: [{key: value}], file: name, left: n}`, typed by the column types (numbers as numbers, dates as ISO). It is all or nothing: on `refused`, nothing was stored, so sending again is safe.
- The preview reuses the table kind's DOM and CSS (`.tbl`). `import.css` here (tokens only) is everything the kind adds. One container query puts the columns beside the rows at 880 px and wider, and one folds them below 600 px.
- `import.js` and `data.js` here are a preview-only port with the English and Thai words. `page.css` is only for these previews. Run `./render.sh` (Playwright's cached headless Chromium) to make the images.

## Reading and writing files, and the new dependency the issue asked to name

Recommended: no dependency. A reader and writer of our own in a separate chunk, `dist/sheet.js`, loaded by `import()` on the first pick, template or export. `blocks.js` gains only the kind's view.

- .xlsx is a zip of XML files. The reader walks the zip's central directory, inflates with the browser's built-in `DecompressionStream("deflate-raw")` and reads the shared strings and one sheet with `DOMParser`. Date cells are found by their number format. .csv follows RFC 4180, guesses the delimiter (`,` `;` tab), reads UTF-8 and falls back to Windows-874. Old .xls is refused with a message (case 9).
- The writer makes the template, the left-out rows and the table's export as a stored (uncompressed) zip with a CRC-32 over a minimal workbook.
- Swift does the same with Apple's own Compression (raw deflate) and `XMLParser`. Fixtures (a good file, bad rows, wrong columns, a Thai CSV) are shared by the web and Swift tests.
- The alternatives, if the owner prefers a library: SheetJS Community Edition (`xlsx`, Apache-2.0; several hundred KB minified; current builds are published from its own CDN, not npm). Or `read-excel-file` + `write-excel-file` (MIT, smaller, web only). Either way Swift would need its own (e.g. CoreXLSX, Apache-2.0, with ZIPFoundation). Each is a line in `docs/deps.md` and a second code path per language.

The table's export: `export: ["xlsx"]` on a table that holds all its rows (no `more`) writes the file on the device from the shown columns, sort and filter (the ticked rows only, if any) and sends no action. With `more`, or for CSV, it keeps sending the export action, as today.
