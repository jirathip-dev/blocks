10 · Server errors

There are three ways it can fail. The upload fails (the handler refused it, or the network dropped): the file line turns red with [retry]. The app can't use the file (an old .xls, more rows than it takes, no header row): its own message sits above the drop area, and nothing is previewed. The app doesn't answer the read: the same red line, with [retry]. A retry sends the same file id again, so it is safe.

11 · Wrong columns, and a column changed

The app found no column for a required one (Price). Its row turns red with "required: pick a column", its cells in the preview show "—", and the button is off with the reason. When the user picks a column or another sheet, the block sends the read again with the new match. Until the app answers, the rows dim and the bar says it is checking. Errors depend on the match, so only the app's answer can clear them.

12 · A workbook with several sheets

The app picks the first sheet that has a header row and lists the others. A select under the file name changes the sheet, and that reads the file again.

13 · Thai

The block's words follow the screen's language. The labels, the rows and the error text are the app's own.

14 · Off, and with JavaScript off

With no file handler or no import action, the block is drawn off and says so. The static page (JavaScript off) lists the columns a file needs, required ones in bold. The template link still works there, since it is a plain link.

15 · A table's export

Unchanged: a table with export: ["xlsx"] sends its export action, and the app makes the file and sends it. The import block adds no export of its own.
