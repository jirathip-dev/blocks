8 · Wrong columns

The file has no column for a required one (Price). That column's row turns red with "required: pick a column", its cells in the preview show "—", and the button is off with the reason. Optional columns with no match (Category, Best before) are simply empty.

9 · A file that can't be used

Checked before any preview, on the device: a file that isn't .xlsx or .csv (the old Excel .xls included: save it as .xlsx), a file with no rows, more rows than the screen's limit. The message sits above the drop area. Nothing is sent.

10 · A workbook with several sheets

The first sheet that has a header row is picked; a select under the file name changes it. A CSV shows the text encoding it was read in instead.

11 · Thai, a CSV saved by Excel in Thai Windows encoding

A CSV is read as UTF-8; if that fails, as Windows-874, the encoding Excel uses for Thai, and the file line says which. Words follow the screen's language.

12 · Off, and with JavaScript off

With no import action, the kind is drawn off and says so. The static page (JS off) lists the columns a file needs, required ones in bold, and says the import needs JavaScript: the file is never parsed on the server.

13 · The template, and a table's export

[download template] writes "Import products template.xlsx" on the device: one sheet with the column labels as the header row (required ones in bold) and a second sheet with each column's allowed values. A table with export: ["xlsx"] and all its rows on the screen writes its file the same way, from the columns, sort and filter on screen (the ticked rows only, if any), and sends no action. A table with more rows on the server keeps sending the export action to the app.
