## Summary

Decision: the action answer's plain-text toast becomes a `toast` kind with a tone (ok, warn, bad or none), a text and an optional undo that sends an action. It floats at the bottom (centred, 520 px wide on desktop, full width above the tabs on phones) on #57's default look: a card with an ink frame, a 3 px tick and a glyph in the tone, the house `[undo]` and `[×]` buttons, and a thin ink line showing the time left. Only one shows at a time. Up to 3 more wait behind it in order, shown as "+2". The timer pauses while the pointer or focus is on the toast. ok and plain toasts last 4 s, warn 6 s and any toast with undo 8 s. Errors stay until dismissed.
Screens: an orders list right after "archive 3 orders", the queue frame by frame (arrive, wait, hold, undo, error, full), and a sheet of every state and stress case. Each is drawn light and dark, at 1440 and 390.
Open questions: (1) `toast` in the answer changes from a string to an object, a breaking wire change. I recommend bumping `SCHEMA_VERSION` and having the server send just the text to clients one version behind, as `docs/schema/versioning.md` says. The other option is to accept both forms, which leaves two ways to send a toast. (2) Should the app be able to set how long a toast lasts? I left that out; the times come from the tone.

## Rules impl follows

- Data (impl picks the final names in the crate): `type: "toast"`, `id`, `tone` (`ok`, `warn`, `bad` or none), `text`, `undo { label, action, values }` with the label defaulting to "undo", and `fallback` defaulting to "Done". The action answer's `toast` field carries this same object. Replace the string form; don't keep both. The shell's own toasts ("copied", "action failed: 500", a network error) use the same kind: plain for copied, bad for failures.
- Colours are tokens only. The frame is `--l` (`--edge` in the flow). The tick uses `--g`, `--a` or `--r` (`--l` with no tone). The glyph uses `--fk-g`, `--fk-a` or `--r`. The time-left line is `--l` on a `--line` track, and `--mute` while held. The surface is `--card` with no tint and no shadow, and the corners use `--radius`. This replaces today's `.b-toast` with its tone-coloured border.
- Timing: no tone and ok last 4 s, warn 6 s, any toast with an undo 8 s, and bad has no timeout. The clock stops while the pointer is over the toast or focus is inside it. Escape (with focus inside) or × closes it. After one closes, the next waiting toast shows 160 ms later (`--enter`). A toast from an undo's answer goes first. At most 3 wait; a fourth drops the oldest waiting toast that is not bad. Memory stays bounded.
- Undo: one tap sends the undo's action through the same path as any action (a confirm, if it has one, still applies). While it is in flight the button reads "undo…" and is `aria-busy`. When the answer comes back, the toast closes and that answer's own toast, if any, takes its place. If the undo fails, the failure shows as a bad toast.
- Accessibility: the stack sits in a polite live region, and each toast is `status`, or `alert` for bad. The accessible name is the full text, even when it is cut to 3 lines. The glyph and time-left line are `aria-hidden`. "+2" is read as "2 more". × is named "dismiss". A toast never takes focus. Undo and × are the house bracket buttons, with a 44 px hit area through their inset.
- Motion: the toast slides up `--rise` (8 px) and fades over `--enter`. The line shrinks linearly. With reduced motion there is no slide, and the line steps once a second. No clip is needed.
- In the flow: a `toast` placed in a screen (fixtures, `blocks-shot`, the static site writer) draws as a quiet line where it sits, with the edge frame, tick and glyph, but no clock, no × and no undo. A client that does not know the kind draws its `fallback`.
- SwiftUI: an overlay at the bottom with the same parts. Errors post a VoiceOver announcement right away; other tones post a polite one. The React adapter draws the same markup as the web one.
- Stress fixtures: long text (cut at 3 lines), empty text (the fallback), and a long undo label. "Many rows" does not apply, since only one toast shows at a time.

## Files

`toast.css` is everything the kind adds, about 20 rules in the `blocks` layer. It replaces `web/src/css/shell/notice.css`'s `.b-toast` rules. `toast.js` is a port used only to draw these previews; its `left`, `waiting`, `focus`, `busy`, `held` and `inline` fields fake runtime state for the images and are not wire fields. It is not product code. `page.css` is the host page for the previews only. The tokens come from `../neutral-default/tokens.css`. Images are made by `./render.sh` (Playwright's cached headless Chromium, light and dark, reduced motion).
