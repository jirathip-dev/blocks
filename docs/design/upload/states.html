upload · every state

1 · Empty

One file: [choose file]. Many: [add files]. Images only: the word says photo. The hint is drawn from accept and mb, so an app writes neither. With capture, a touch screen adds [take photo] first.

2 · One file, held

A photo shows its thumbnail; any other file a square with its extension. Without many the button becomes [replace]: a new pick replaces the one file.

3 · Uploading, done, failed

Uploading: the thumbnail dims and a 4 px ink bar fills under the name; [remove] aborts it. Done: the size. Failed: a 3 px red edge, "upload failed", [retry] and a red [remove]. Remove takes the id out of what is sent.

4 · Refused before the app sees it

A wrong type or a file over mb never reaches the file handler. It stays in the list with a "!" square, a red edge and the reason, until [dismiss] or the next pick.

5 · The app's own answer, and off

The app checks the bytes again; its error is the field's note in red, as on any field. With no file handler passed in, the field is drawn off and says so.
