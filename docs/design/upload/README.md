## Summary

Decision: the upload field is a list of file rows under its label. Each row has a 56 px thumbnail (or a square with the file's extension), the name, one status line (size, "uploading 62 %" over a thin ink bar, "upload failed", or a red "refused: …") and its buttons: [remove], [retry] or [dismiss]. When the field itself is narrow (a phone, or a small card), the buttons go under the name, so short names and the status line stay whole. Under the list are [add photos] / [choose file] / [replace] and a hint built from `accept` and `mb`. On a touch screen with `capture`, [take photo] comes first. The submit stays off, with a line saying why, while a file is uploading or failed. With no file handler the field is drawn off. With JS off, the static page shows the browser's own file input with the same hint, in a row as tall as the live one. The app's error sits above the list, in the list's column. Default look, no new colour.
Screens: a delivery proof form (uploading, empty, failed), a sheet of every state (empty, one file, many, progress, failed, refused for type and for size, Thai, the app's error, off), and the static page next to its live version. Each is drawn light and dark, at 1440 and 390.
Open questions: none. This round follows the owner's revise q2472.

## What impl builds

- `web/src/render/field/upload.ts`: the root is `div.fu` with `role=group`, named by the label and the file count. Inside it is `ul.fuf` > `li.fui.<state>`: `img.fut` (aria-hidden) or `span.fux`, then `span.fum` (`.fun` name, `.pgt` progress bar with `role=progressbar` while uploading, `.fus` status line), then `span.fua` buttons, each named "remove <file name>" and so on. An app error is `span.fe` first in `div.fu`, above the list. Then `div.fub`: [take photo] `.fuc`, the pick button, the `.fuh` hint, and a hidden `input[type=file]` the buttons click.
- `busy()` is true while any row is uploading or failed. The form turns the submit off and writes the `.say-busy` line.
- The words (choose file, add files, add photos, choose photo, take photo, replace, remove, retry, dismiss, the hint, uploading, failed, the two refusals, off, the two busy lines) go in the field's words table in English and Thai. Their text is in `upload.js` here.
- `upload.css` here (tokens only) goes into the stylesheet folder. It reuses `.fd`, `.fn`, `.pgt` and the button. `div.fu` is a size container. Below 440 px of its own width a row puts its buttons under the name (a container query, not a screen width). The camera button shows on `(pointer:coarse)`. The static page reuses `.fd.up > .fu > .fub` with `input.sf` and `.fuh`. In these previews it shows at 390 wide instead, since headless Chromium has no touch.
- `page.css` and `upload.js` are only for these previews, like in `docs/design/steps`. Run `./render.sh` to make the images (Playwright's cached headless Chromium, light and dark, reduced motion). The photos are three small SVGs in this folder.
- A multi-field form with a submit is drawn here as a card with the submit at the bottom right. How such a form is laid out is not part of this issue.
