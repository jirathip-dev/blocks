## Summary

Decision: a message is a two-column row: a 28px square avatar (or the speaker's initial, in ink for the owner), then the name in bold and the role word, then its blocks in the order they were said. The owner's text sits on a 3px ink mark, a system message is a muted line between two rules, and a second message by the same speaker has no head. A tool call is one 44px row (↻ running, ✓ done, ✕ failed in red with a red mark, the name in the code face, a one-line summary, › to open its plain-text body). Streaming shows an ink caret after the last character. It blinks, and stays still when the user asks for reduced motion. Attachments show images as an 88px strip, then the files one per row with the extension in front. It uses the default look with no new colour.
Screens: a thread with a reply streaming in, that reply frame by frame with the op behind each frame, and a sheet of every state. Each is drawn light and dark, at 1440 and 390.
Open questions: (1) Should a second message in a row by the same speaker drop its head (drawn here), or keep it every time? Dropping it means a renderer compares each message with the one before it. (2) Decided (q2779): `message` has an optional `time`, drawn after the role word in the same muted face; omitted when unset.

## What impl builds

- **Markup** (`shapes.md` hooks): `article.msg.b.b-message[data-variant=role]` holds `img.mav.b-message__avatar` (or `span.mav.ini` with the first letter, `aria-hidden`; none for `system`), `.mh` > `span.mn.b-message__name` + `span.mr` (the role word), and `.mb` (the blocks, then `.mf.b-message__files`). A message whose role and name match the one before it in the same list gets `.cont`.
- **Tool**: `.tol.b.b-tool[data-variant=state]`. With a `body`, the head is a button (`aria-expanded`), or `<details>/<summary>` on the static page; with none, it is `.toh`. Inside the head: `i.tog` (↻ ✓ ✕, `aria-hidden`), `span.ton.b-tool__name`, `span.tos.b-tool__summary`, `span.toc` (›, only with a body). The body is `pre.tob.b-tool__body`. A running tool is `aria-busy`.
- **Attachment**: an image goes in `.mfi` as a link or button holding `img[alt=name]`. A file is `.mff`, named by its full `name` with that as its `title` too, holding `span.mfx` (the text after the last dot) and `span.mfn` (the text before it).
- **Streaming**: `aria-busy="true"` on the prose and nothing more; the caret is CSS only (`::after` on the last text-bearing child, `::before` on an empty block), so growing the text in place does not touch it. `blocks.css` hides an empty `.prose`; a busy one shows.
- `message.css` (tokens only, in the stylesheet folder) is the kind's CSS. Its class names were checked against `blocks.css`: `.tl`, `.th`, `.tg`, `.tb` and `.fn` are taken, so the tool uses `to*` and the files use `mf*`. SwiftUI and egui draw the same parts with their own tokens: the avatar or initial column, the name and role line, the 44px tool head with the state glyph and the folded body, the caret after the last text, and the image strip then the file rows.
- `page.css` (#53's page and tiles), the `.svg` stand-in avatars and images, and the `.op` captions are only for these previews. Run `./render.sh` to make the images (Playwright's cached headless Chromium, light and dark, reduced motion, so the caret and ↻ are still).
