Decision (revised after q2187): the showcase site wears the approved grey tile look, turned up: a wide two-column hero with a 64 px title and a slower, deeper build-up on the home page; every page is one blocks screen (link bar, page title, tiles on the dot grid); the gallery draws all 27 core kinds (one count, home and gallery) from fuller samples the site builds with the typed API, and the build works out from the renderer which kinds have no HTML view yet (7 today) and marks them *this is its fallback*; every page's buttons are #53's grey-edged boxes and its chips and tags square with a grey edge; schemes show the default pair and the site's own Paper side by side with JS off, and the look sheet switches the whole site with JS on; numbers show the browser bench from `docs/bench-blocks.json`, its memory figure labelled as the browser process (WebContent RSS) after 1,000 updates, and CI's six perf budgets.
Screens: home, gallery, one kind's page (stat), schemes (plus the look sheet open), numbers, behaviours, islands; each at 1440 and 390 wide, home and gallery also dark.
Open questions: none. The owner settled the last round's three: one page per kind stays beside the gallery, Paper stays light only, and measured perf times beside the budgets come in a later issue.

## Decisions

- **Every page is a blocks screen.** Link bar (`nav`), page title (the screen's title), then blocks. The site's CSS styles only the hooks (`.b-*`, `data-block`, `data-id`) on top of `blocks.css` and the default tokens; the mockups load `web/src/blocks.css` and `../neutral-default/tokens.css` as they are.
- **The tile look, turned up.** Each top-level block is a white square tile with a 1 px edge on the dot grid, 2 px seams within a group; section labels sit on the page. Text is 15 px instead of 13. The home hero's title is 64 px (40 at 390). The home page's build-up is slower and deeper than the default: each tile rises 24 px over 520 ms, starts 90 ms apart, and the last starts by 720 ms. The other pages keep the default build-up. Reduced motion: none.
- **Links, not forms.** The hero's actions are acts with a URL, so they render as `a.btn` and work with JS off. No page posts anything: Pages has no server.
- **The gallery draws fuller samples (q2187).** Each kind's sample is defined in the site with the typed API and drawn by the real HTML renderer; the mockup writes the markup the renderer gives for it. A kind's own page (`kind-stat`) still shows its `fixtures/blocks` sample. The kind list comes from the kinds the crate knows, and the fallback-only group is every kind the renderer draws through its fallback, so neither is a fixed list: the count on home and the gallery is that one number (27). The sample pictures stand in as `media/sample.svg`.
- **Shared controls as #53.** Buttons are square boxes with a 1 px grey edge (primary filled with ink, destructive with brick text, disabled greyed), never brackets; chips and tags are square with a grey edge, the picked chip filled with ink. The site's CSS sets this on the button, chip and tag hooks, so it holds on every page.
- **Paper, the site's own scheme.** Warm greys and an ink-blue accent; the state colours of the default, with brick and ochre a touch darker for the warmer page. Measured contrast on page and card: text 14.7 and 16.3, muted 6.6 and 7.3, accent 9.0 and 10.0, brick 4.9 and 5.4. It must pass `theme::gate` in CI; impl adjusts a value if it does not.
- **Sub-path and head.** Every link is relative, so the site works under `/blocks/`. Each page sets its title, description, `og:*` and `twitter:card` tags.

## Files

`build.mjs` writes the pages from its own samples, `fixtures/html` (for the kind page and to find the fallback-only kinds), `fixtures/blocks` and `docs/bench-blocks.json`; `render.sh` runs it and renders the PNGs with Playwright's cached headless Chromium (settled, reduced motion). `site.css` is the site's own stylesheet over the hooks; impl ports it. `media/` holds the hero picture and the sample picture. These files are mockups only: the real site is a Rust generator writing each page with `site::page`.
