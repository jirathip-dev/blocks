## Summary

Decision: `table` is one tile on blocks' default look: a grid with a bar (title, row count, one filter box, columns, export), grey headers you tap to sort, and a bold totals row that follows the filter. Columns are text, number, money (฿, 2 decimals), date (with an optional Buddhist-Era year), badge and a small bar. Tick boxes turn the bar into a bulk-action bar; export and bulk actions only send an action, and the app does the work. The header, first column and totals stay put while the grid scrolls. Under 600px wide it becomes stacked phone rows with the bar stuck to the top.
Screens: an invoices page (two rows ticked), and a sheet of every state (column kinds, sort, filter, no match, empty, wide and tall, column hide and width, select and bulk, export, row diff, phone rows, static page, fallback). Each light and dark, at 1440 and 390.
Open questions: (1) While rows are ticked the bulk bar replaces the filter, sort and columns controls (export stays and exports the ticked rows). OK? (2) A Buddhist-Era date keeps English month names ("19 Nov 2569"). Should it use Thai month names instead? (3) A tall grid scrolls inside the tile (at most 70% of the window) so its header and totals can stick; the alternative is a page-length grid whose header sticks to the screen but whose totals sit at the very end. Inside the tile OK?

## Decisions

- **Shape.** `columns`: `id`, `label`, `kind` (`text`, `number`, `money`, `date`, `tone` or `bar`), plus the optional `align` (`start` or `end`; the default is end for number, money and bar, start for the rest), `unit`, `digits`, `currency` (money: an ISO code, `THB` drawn ฿), `era: be` (date), `max` and `tone` (bar), `total` (`sum`, `avg` or `count`), `sort: false`, `hide: true` (starts hidden), `width` (in characters) and `phone` (`title`, `tag`, `value`, `meta` or `hide`). `rows`: `id`, `cells` keyed by column id, and an optional `tap` (the existing `Tap`). On the table: `title`, `sort` (`{by, dir}`, the starting order), `filter: false` to drop the box, `empty`, `select` (`actions`: each an `action` id, a `label` and an optional `bad`) and `export` (a list of `csv`, `xlsx`). A tone cell, the "badge" of synergy's inventory, is the existing `Label` (`text`, `tone`) drawn as the existing `.tag`.
- **Formatting is fixed, not locale-driven,** so every renderer and `blocks-shot` agree. Numbers use en-US grouping and at most 2 decimals (or `digits`). Money always has 2 decimals; its sign sits in the header, not in each cell, and in the fallback's total. A date is an ISO `YYYY-MM-DD` drawn as "19 Nov 2026", or "19 Nov 2569" with `era: be` (the year plus 543); it still sorts by its ISO value. Nothing reads a clock. A blank cell (`null` or missing) draws nothing.
- **Bar cell:** the number with a 48px bar before it, filled to value ÷ `max` (else the largest value in all the rows, so the filter does not rescale it), in the column's tone. It sorts and totals as a number.
- **Sticky:** the grid scrolls inside the tile once it is taller than 70% of the window: the header row sticks to its top, the totals row to its bottom, the first column (after the tick box) to its left. On a phone the page scrolls and the bar sticks to the top of the screen.
- **Column hide and width:** a [columns] button (on any table with 3 or more columns) opens a list of tick boxes; the first column cannot be hidden. The choice is the renderer's, kept per block id; the button reads "columns · 2 hidden". The filter searches only the shown columns. `width` fixes a column in characters; longer text ends in … with the full text as the cell's title.
- **Select and bulk actions:** with `select`, each row gets a tick box and the header one ticks every shown row (a dash when some are). Once anything is ticked the bar turns grey: "N selected", one button per action (red if `bad`), [export], [clear]; the filter, sort and columns controls step aside until it clears. A bulk action sends `Action{block, action, values: {rows: [ids]}}` and the app answers as for any action. Hiding a row by filter, or removing it by patch, unticks it. Ticking does not trigger the row's `tap`.
- **Export:** blocks draws the control and sends an action; it never builds a file. One format: [export csv]; two: [export] opens a menu. It sends `Action{block, action: "export", values: {format, columns, sort, q, rows}}` (the shown column ids, the sort, the filter text and the ticked ids, or none), so the app can build the file that matches the screen.
- **Sort:** one column at a time, stable. Tapping a header goes ↑, then ↓, then back to the block's own order. Blank cells go last in both directions. Text sorts case-insensitively, a tone column by its text, a date by its ISO value. The header gets `aria-sort`.
- **Filter:** one box. Every word must appear in some cell's drawn text, case-insensitive. The count reads "N of M rows", and the totals cover only the rows shown. When nothing matches, it says "No rows match “x”" with a [clear] button.
- **State is the renderer's.** The sort, the filter text, the hidden columns and the ticks are local to the screen and kept per block id across updates, like `diagram`'s "was N". The app only sees them inside an export or bulk action.
- **Row diff:** rows are keyed by `id`, so a patch updates, adds or removes one row without redrawing the table. A changed or new row gets the 3px ink edge (as `diagram` does) until the next update, and a new row fades in through `b-late`.
- **Phone:** there is one DOM, a real `<table>` (with a hidden caption). A container query (`.tbl` is the container, under 600px) hides the head and lays each `tr` out as a row: title, tag, value, ›, then a meta line of `label value` pairs. If `phone` is not set, the first text column is the title, the first tone column is the tag, the last number or money column with a total (else the last such column) is the value, and everything else is meta. With `select`, the tick box leads each row and the select-all box moves into the bar. No JS measuring, so the static page gets it too.
- **Static site writer:** the same `<table>`, every column (`hide` is ignored), in `sort` order with the totals worked out, and no filter box, sort select, header buttons, tick boxes, columns or export.
- **Fallback** (a renderer without `table`): one row with the title, the first summed column's total, and "N rows".
- **Left for a follow-up** (owner, q2274): per-column filters (value pick, number and date ranges). Totals are the one aggregate the column names; tapping a total does not cycle it.
- **SwiftUI:** a `Grid` when the width is 600 or more, else the same phone rows (a `List` of the row anatomy), with the same formatting, sort and filter rules, the same bulk bar and export actions, a pinned header (`Grid` inside a `ScrollView` with the header row outside it) and the columns menu as a `Menu` of toggles.

## What impl builds

- The kind in the crate (`Table`, `Column`, `TableRow`, `BulkAction`, with `Label` reused for tone cells and the existing `Action` for bulk and export), then `just gen` for the schema, TS and Swift, and `fixtures/blocks/table.json` (the invoices here, trimmed).
- `web/src/render/table.ts` draws the DOM above; there is no `gap(` for `table`. `table.css` here, about 70 rules using only tokens, goes into `web/src/blocks.css`, and `.tbl` joins the tile rule.
- The site writer's element, the fallback, and keyed row ops in diff/patch. `blocks-shot --check` at 1440 and 390, and a SwiftUI render test.
- `table.js` and `data.js` in this folder are a preview-only port that draws these images; they are not product code. Images: `./render.sh` (Playwright's cached headless Chromium, light and dark, reduced motion).
