nav, hero, prose, media: a site page in SwiftUI

One screen of the four content kinds, in order: nav, hero (with its media), prose, then a video media. Built-in default, light. Each block is a square tile; nav spans the width, the rest keep to one readable column (720 pt at most), with the page's dot grid showing at the sides and through the 3 pt seams.

Blocks

Typed screens, sent as JSON and patched by ops. A prose block is a tree of parts, so no renderer needs a markdown reader; see the schema and Prose::new().

  • one schema, 27 kinds
  • a fallback for every app kind
  • patches, not repaints
  1. build the screen
  2. send it
  3. patch it as it changes
Built by type, drawn by every renderer.

Spans can be bold, italic, code or a link; the text is selectable.

nav: the brand at the left in ink, links at the right; the current link is ink with an underline, no tint. At phone width the links scroll sideways under a fade, with no menu button. hero: title, subtitle, media, then its actions (the first one primary, in ink). media: its tile takes width×height before the picture loads; alt shows until then; a video shows its poster and a square play button and plays in place. On first load the tiles settle in top to bottom (nav, hero, prose, media), 40 ms apart, done in 0.32 s.
